Evaluation architecture

One product objective. Many kinds of evidence.

Linger objectives describe end-to-end product behavior. Component suites isolate what each agent or service contributes. Synthetic datasets supply multiple scenarios; graders turn observed runs into evidence.

The central distinction

A Serendipity behavior is not a Linger objective. It is one component responsibility inside one or more Linger objectives.

01 · hierarchy

The evaluation model

Each level answers a different question. Keeping those questions separate prevents a passing agent contract test from being mistaken for proof that the full experience works.

Linger objective

The end-to-end behavior the product must demonstrate. It names the user-visible outcome, participating components, gates, and measures.

Dataset

A versioned collection of scenarios chosen to measure that objective: curated baseline, synthetic, adversarial, or held-out.

Case / scenario

One concrete world: state, inputs, available evidence, permissions, expected outcome, and prohibited outcome.

Grader & measures

Deterministic gates and separate semantic judgments, aggregated into objective-level measures.

Run & report

Observed behavior from a specific model, prompt set, code version, and dataset version, with traceable results.

Cardinality matters

One objective should be supported by multiple cases, usually across multiple datasets. A dataset contains many cases. A case may exercise one primary objective and compatible overlays.

02 · scopes

End-to-end evidence and component evidence are complementary.

The two scopes diagnose different things and should remain visibly distinct.

Linger-wide

Objective evaluation

Runs the product path needed to deliver a user outcome. Multiple agents, policy gates, services, and handoffs may participate.

  • Answers whether Linger delivers the capability.
  • Uses objective-linked synthetic scenes and adopted Ground truth.
  • Measures released outcomes, safety, grounding, and lifecycle behavior.
Focused

Component evaluation

Isolates an agent or service responsibility and tests its accepted behavior contract with controlled inputs.

  • Answers why a product path passed or failed.
  • Includes Muse, Serendipity, Sculptor, Provenance, and Librarian suites.
  • Does not prove the end-to-end objective by itself.
03 · lifecycle

Synthetic data moves from design to evidence.

The generated material is evaluation input, not an evaluation result. Ground truth becomes authoritative only after validation and independent adoption.

1Select objectives

Choose the smallest coherent set from the catalog.

2Author packages

Create Backstory, Props, Scenes, Lines, and proposed Ground truth.

3Validate

Check schemas, references, hashes, spans, and composition rules.

4Adopt Ground truth

An independent human approves, revises, or rejects proposed labels.

5Replay & grade

Run production paths and record gates, semantic review, traces, and reports.
