Subsystem design & progress · 25 Aug 2026

Find the right evidence. Reveal nothing beyond the reader.

Librarian prepares an exact book corpus offline, then retrieves spoiler-bounded evidence online. It returns a clarification, a completed result, or a safe failure—never a user-facing answer.

Four non-negotiables

1Canonical text stays exactRouting metadata and indexes are never citable truth.
2Scope comes before searchForbidden chapters never reach a tool, reranker, or model.
3Clarification is not a resultIf scope is unclear, retrieval does not run.
4Evidence is not release authorityMuse drafts; Provenance and application checks gate output.

One subsystem, two flows

The offline output becomes the online source of truth. Search indexes can be rebuilt; canonical chapter bodies cannot be silently changed.

Flow 01 · offline

Corpus preparation

Use a small source-specific adapter with the shared lifecycle to create exact Markdown chapters and a compact routing catalogue.

1Verify immutable source hash
2Validate real chapter structure
3Write exact canonical chapters
4Derive metadata-only catalogue
5Build disposable evaluation indexes
Flow 02 · online

Bounded evidence retrieval

Validate the reader’s boundary, search only permitted material, and return a typed hand-off to Muse.

1Validate access and reading position
2Clarify, or expose eligible catalogue
3Retrieve, fuse, deduplicate, rerank
4Judge sufficient, weak, or none
5Return exact canonical evidence

Deferred future memory schema

Memory is a separate service, not a Librarian responsibility. This preserved design adapts public store, document, version, and read-only access patterns for a possible future product slice; no implementation is planned for the current POC.

Proposed record model

In the deferred design, one stable live record points to its current immutable version and generated knowledge remains separate.

memory_storeTrusted account scope and lifecycle boundary
↓ contains
memoryStable memory_id · current Markdown · path · content hash · current_version_id
↓ appends on every mutation
memory_versionDistinct version_id · created, modified, or deleted · previous_version_id
memory_derivationSeparate replaceable summaries and relationships citing source version IDs

Proposed behaviour

Create would never overwrite. Correction and deletion would require the current content hash, every mutation would append an immutable version, and read-only agents would receive only the minimum projection.

Preserved authority rule

Muse and Sculptor would submit typed proposals; only the Memory & Policy Service would own account scope, consent, IDs, paths, idempotency, and writes.

    Three responses, three meanings
    The top-level kind is a strict switch for Muse. A question, an empty result, and a system failure cannot be handled as the same thing.
    kind: clarification
    Retrieval did not run
    The reading boundary is missing or ambiguous. The response contains one focused question and the expected answer shape.
    Muse asks the question. It does not draft a book answer.
    kind: result
    Retrieval completed
    The outcome is evidence found or no evidence; strength is sufficient, weak, or none. Weak still carries evidence details.
    Muse drafts with returned evidence and limitations.
    kind: failure
    Could not complete safely
    A dependency failed, an evidence ID did not resolve, or integrity validation failed. No unvalidated passage is returned.
    Orchestration retries or uses a safe application message.
    

    
    Ranking is not evidence strength
    A similarity score tells us which passage looks related. Librarian’s final judgement asks whether all eligible evidence can actually answer Muse.
    Tool · candidate gate
    Retrieval threshold
    Keep candidates similar enough to inspect. Semantic score starts at 0.5.
    Tool · ordering
    Reranker
    Order up to 15 permitted candidates by relevance to the exact query.
    Agent · set judgement
    Evidence strength
    Label the combined result sufficient, weak, or none—and explain why.
