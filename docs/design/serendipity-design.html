Optional reasoning specialist · Search, compare, decline

Serendipity

Serendipity looks for a connection only when Muse asks. It searches sources the application explicitly grants, filters unsafe or weak material before ranking, compares two or three distinct candidates, and returns one proposal—or a deliberate decline. It never speaks to the reader directly.

01 · Authority

Useful initiative inside a sealed grant.

The model may choose how to search and compare. Trusted application code fixes which sources exist, which book revision is valid, how far the reader has reached, and whether any result can progress toward release.

May decide

The primary search source, concise search queries, whether evidence is sufficient, one justified source expansion, candidate bridges, shortlist order, and whether declining is safer than forcing novelty.

Must preserve

The active cue, intent, presentation mode, allowed source list, immutable book revision, chapter ceiling, exact evidence identifiers, and the application-owned search ledger.

May never decide

Account identity, new source access, spoiler authority, public release, durable memory writes, citation trust, or whether web content may bypass Muse, Provenance, and deterministic validation.

02 · Implemented flow

Search, shortlist, compare, validate.

A source grant is permission—not an instruction to search everything. The agent starts with the relationship the reader requested, expands only for a material reason, and stops once two eligible candidates can be compared.

03 · Source routing

Follow the requested relationship.

Ordering in allowed_sources never determines search order. Serendipity identifies the reader's requested domain and refuses silent substitution when that domain was not granted.

Cue or intentPrimary routeExpansion rule
Another passage, chapter, character, or pattern in a confirmed workLibrarianAdd web only when explicitly requested or bounded book evidence is insufficient and outside comparison is materially useful.
Essay, artwork, song, thinker, recommendation, or outside ideaExaAdd the confirmed book only for an explicit comparison or when it is necessary to make the outside result useful.

Ambiguous reflection without a specific evidence relationshipDecline when no source fitsNever search the public web simply to manufacture novelty.
04 · Safety & provenance

Hard gates before model ranking.

Semantic judgment can narrow a result but cannot widen application authority. The model, tool wrappers, typed contracts, orchestration, and final release validator each enforce a different boundary.

01
Application-owned grantOnly current book scopes and explicitly enabled web access become tools for this run.
02
Guarded retrievalBook queries are clamped to revision and chapter. Web queries are bounded, generalised, and checked for personal data or copied reader wording.
03
Exact web lead chainget_page may open only a URL returned by this run's web_search; unopened search results are not evidence.
04
Typed proposal invariantsTwo or three distinct eligible candidates, descending anchors, one clear rank-one winner, and unchanged presentation.
05
Deterministic ledger validationEvery shortlisted ID must resolve to exact in-scope evidence recorded by a permitted search in this run.

Anchored candidate rubric

Ordinal categories, never a confidence sum.

Any disqualifier rejects eligibility: generic-only, insufficient support, scope risk, privacy risk, spoiler risk, or prompt injection. Eligible candidates are ordered lexically; values are never added into a synthetic score.

05 · Output contract

A decline is a successful answer.

Serendipity produces exactly one typed decision. Rejected candidates and losing evidence remain inside the run instead of leaking into Muse's context or the reader-facing response.

ConnectionProposal

  • Two or three distinct eligible candidates
  • Selected ID must equal the rank-one candidate
  • Exact evidence IDs and comparison notes
  • Qualitative uncertainty, unchanged presentation, and safe follow-up
  • contains_web_claim exactly when the winner cites web evidence

ConnectionDecline

  • Machine-readable reason such as insufficient evidence, generic theme, no clear winner, unsafe evidence, or unavailable retrieval
  • Application replaces model-authored next steps with one fixed safe message
  • No rejected candidate evidence leaves the boundary
  • Counts as a valid outcome—not an agent failure
06 · Release boundary

Proposal is not publication.

The selected candidate remains untrusted preparation for Muse. Citation and release authority stay outside Serendipity from discovery through display.

Serendipity → Muse

Winner only

The application packages the validated decision with only the exact records cited by the winner. Losing-candidate evidence is discarded.

Muse → Provenance

Complete draft

Muse decides whether and how to use the proposal, declares book evidence, and submits the entire reader-facing candidate for independent review.

Application → Reader

Fail closed

Selected book records may enter the trusted request-scoped evidence map. Any selected web evidence is currently blocked from public release.

07 · Current status

Operational slice and explicit gaps.

The implementation supports bounded book discovery end to end and guarded web discovery internally. Broader evidence authority remains deliberately incomplete.
