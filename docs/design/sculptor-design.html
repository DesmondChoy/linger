Reasoning role · Design & progress

Sculptor

The memory-curation specialist examines a bounded account-scoped set and proposes exactly one retrieval-oriented change—or no change. It preserves every original, has no tools or storage authority, and leaves validation and application to deterministic services.

Sc
Curation specialistProposal slice
01 · Responsibility

Curate derivations, preserve originals.

Sculptor improves future retrieval without silently rewriting the reader’s record or granting itself policy authority.

May decide

Whether supplied memories are duplicates, benefit from a concise derived summary, belong in a retrieval topic group, or should remain unchanged because support is ambiguous.

May not decide

Which account or memories to inspect, what should be captured, whether a proposal is stored, or whether an original may be edited or deleted. It has no tools, network access, or filesystem access.

02 · Implemented flow

A bounded proposal, then deterministic validation.

Application code selects two to twelve memories from one trusted account scope. Sculptor can cite only those IDs and can never claim that a change was applied.

01 · Application

Select bounded input

Resolve account scope and supply only the minimum text needed for curation.

AccountScopedMemories { account_scope, memories[2..12] }
02 · Sculptor

Treat text as data

Ignore instructions inside memories and compare their durable meaning.

CuratableMemory { memory_id, text }
03 · Choice

Propose one action

Link true duplicates, update a supported derived summary, assign a topic, or decline.

link_duplicates | update_derived_summary | assign_topic_group
04 · Contract

Cite supplied IDs

Every action cites two to twelve unique source IDs; summaries and labels are bounded.

CurationProposal | NoCurationProposal
05 · Validator

Reject drift

Strict models reject unknown fields, repeated IDs, out-of-scope sources, and oversized output.

typed deterministic validation
06 · Future service

Apply derived change

A separate authorised path may store a derivation while originals and version provenance remain intact.

proposal ≠ write

04 · Verification

Small, focused, and qualitative.

The fixed pack distinguishes semantic duplicates, related topics, summarisation opportunities, and superficial similarity that should produce no change.

Focused tests10

Strict inputs and outputs, proposal branches, source validation, preservation rules, and model-agent behavior.

Fixed eval cases5

Exact duplicate, paraphrased duplicate, noisy-memory summary, related topic group, and superficial-similarity no-change.

Live evidence—

No checked-in provider-backed report; the frozen cases run through the evaluation harness.
