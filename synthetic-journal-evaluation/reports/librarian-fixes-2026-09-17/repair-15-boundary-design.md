# Boundary reliability before iteration 15

Pigeon14's ambiguous-growth request received a chapter-5 grant. The model quoted real reader spans, then asserted that they identify mushroom size changes although the reader supplied no mushroom detail. A later chapter-12 growth passage was present but placed in the unreasoned `other_evidence_ids` array. Exact span membership and a complete inventory did not establish semantic uniqueness. The resulting answer retrieval was unauthorized; a later Provenance decline prevented public plot disclosure but is not dependable boundary protection.

Farm13/14 incomplete inference outputs have `finish_reason=content_filter`. They must remain classified as provider-filtered incomplete execution, not uncertain event identification or strict-support mismatch. No filter bypass, source rewriting intended to evade filtering, extra retry, model switch, or gold change is proposed.

Three possible interventions:

1. Add/reorder a resolved-versus-unresolved field in the existing candidate output. This is small, but the same model already asserts a selected occurrence and high confidence. Another self-asserted boolean supplies no materially independent evidence.
2. Require reasons for every omitted candidate. This closes the unreasoned bucket syntactically, but adds output burden to an already large task and can still misclassify alternatives. Do not implement this merely to turn the known example red.
3. Add a focused, independent current-event identification precondition before accepting a proposed chapter grant. Use the same reusable Librarian Agent with a separately selected skill, not a new role or external grader. Its input contains original reader wording and the full private candidate set, but no memories, proposed chapter or first judgment. Return either a reader-identified occurrence with exact distinguishing reader spans and canonical record IDs, or unresolved identification. The application validates input bindings, compares the identified occurrence/derived chapter with the proposed stop, and grants nothing on disagreement, uncertainty or execution failure. This adds one bounded same-model call only for positive chapter proposals; passage authorization remains separate.

Option 3 has the clearest causal intervention: it separates identifying the current event from proving earlier remembered knowledge, and requires agreement without sharing the first answer. It remains fallible semantic model judgment, not a deterministic uniqueness proof. It needs explicit integration agreement because of the added per-positive-call cost and the need to define occurrence compatibility without requiring the same arbitrary retrieval window.

If option 3 is accepted, keep canonical quote/ID binding, all existing memory and scope checks, and fail-closed release intact. First test an injected independent unresolved judgment against the saved unsafe candidate, identified matching and mismatching occurrences, malformed reader/source references, and failure handling. Local tests establish that the gate is enforced, not that the live model will classify correctly. Observe the unchanged Pigeon positive and ambiguous pair in the next authorized run before claiming reliability improvement. Removing the exhaustive inventory from the original grant task is a separate simplification to consider only once the focused gate's contract is agreed; it must not silently remove required proof checks.

No runtime edits or provider calls have been made at this design checkpoint.

## Implemented contract and verification

The parent approved option 3 and its per-positive-call cost. `LibrarianEventIdentificationInput` contains only `current_line`, `prior_reader_statements`, and the full private canonical candidates. `BoundaryEventIdentified` returns canonical IDs, exact reader spans including the current line, and one concise explanation; `BoundaryEventUnresolved` has no grant fields. The original candidate inventory, memory assessments, excerpt bindings, confidence and authorization checks remain intact.

After those checks pass, `infer_spoiler_boundary` invokes `identify_reader_event` through the existing reusable Librarian Agent and the separately selected `EVENT_IDENTIFICATION` skill. There is no first-response or stored-memory content in the second prompt. Every selected record must be from the proposed final chapter and overlap an original selected final-occurrence record, with identical work, version, chapter identity and source hash. Earlier memory support cannot stand in for the selected final occurrence. Overlapping canonical windows may differ in their IDs. The original chapter and supporting locations are retained only on agreement; disagreement, unresolved identification, malformed anchors and execution failure return content-free clarification. Existing line-only, low-confidence, uncertain and passage branches do not run the new check. The existing skill retry budget is unchanged.

Both calls use `run_agent_traced`, with distinct stages, skills and fingerprints; identification failures retain the `event_identification_model_failed` code and the ordinary diagnostic category. The shared evaluation manifest includes the new fingerprint. The source texts and semantic explanations stay private.

The initial regression failed because an otherwise-valid chapter proposal was granted despite an injected unresolved identifier. It passes with the gate. The focused boundary/route/runtime/passage suite passed **170 tests and 42 subtests** (`local-boundary-repair-15.log`). Two subsequent real FunctionModel regressions also passed, bringing `test_boundary_event_identification.py` to **12 tests**: the actual shared Agent saves both complete exchanges without cross-call judgment contamination, and an invalid identification exhausts only the existing repair budget while preserving its own failure transcript. Provider requests are disabled by the test suite. No live call was made during this repair.

These tests prove enforcement and traceability, not that the independent same-model judgment is semantically infallible. Live iteration 15 must still evaluate the positive and ambiguous stops. Interval overlap is compatibility between supplied canonical windows, not an independent claim that every sentence in overlapping windows describes the same event; the selected skill remains responsible for semantic occurrence identification.
