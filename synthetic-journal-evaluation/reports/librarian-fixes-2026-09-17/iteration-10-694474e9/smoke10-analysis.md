## Narrow future provider diagnostic proposal

The installed PydanticAI OpenAI adapter wraps `openai.APIConnectionError` as `ModelAPIError` while retaining the original exception as `__cause__` (`.venv/lib/python3.12/site-packages/pydantic_ai/models/openai.py:202–212`). `APITimeoutError` subclasses `APIConnectionError` (`openai/_exceptions.py:107–114`). The async OpenAI request loop maps exhausted timeout exceptions to `APITimeoutError` and other exhausted send exceptions to `APIConnectionError`, preserving causes (`openai/_base_client.py:1714–1744`). Its defaults are600 seconds overall with5 seconds for connect and two SDK retries (`openai/_constants.py:8–10`); these defaults and root's constructed-client inspection do not prove the actual failure type here.

A minimal evaluation-only extension is nullable `provider_error_kind: Literal["http", "timeout", "connection", "other"]`. Classify only an outer known `ModelAPIError`: `ModelHTTPError` means http; otherwise examine its immediate explicit cause for `APITimeoutError` first, `APIConnectionError` second, then `APIStatusError`; unmatched known API errors are other, and non-provider errors are null. Do not inspect strings, arbitrary status attributes, `__context__`, request objects, URLs, response bodies, model names, or unbounded exception chains. Keep the existing status field's400–599 constraint. An immediate APIStatusError with an anomalous status below400 can identify the HTTP category without copying that status into the constrained field.

This matches the installed wrapper directly and needs no new SDK dependency, retry or stage. An offline probe confirms timeout → ModelAPIError/APITimeoutError cause; connection → ModelAPIError/APIConnectionError cause;503 → ModelHTTPError; and302 APIStatusError → ModelAPIError/APIStatusError cause. These are synthetic local exceptions, not diagnoses of the saved failures. The label connection describes the SDK's connection-error category, not prove a DNS/TLS/remote-network root cause: that SDK branch also catches other send exceptions. Closed-enum tests should cover these wrappers, generic errors with misleading attributes/causes, no sensitive text serialization, and historical missing-field readability.
